# API contract

The application listens on loopback port 8765. n8n listens on loopback port 5678. All protected routes require `Authorization: Bearer <role token>`. Tokens are generated independently; admin, worker, intake and simulator roles cannot substitute for one another.

## Source webhook

`POST http://127.0.0.1:5678/webhook/intake-rescue/enquiry` uses the intake token. Website, partner form and event adapters all send this contract:

```json
{
  "source": "website",
  "event_id": "form-123",
  "name": "Alex Example",
  "email": "alex@example.test",
  "phone": "07700 900123",
  "message": "Please send a quote.",
  "permission_to_reply": true
}
```

`source` and `event_id`: stable identifiers containing 1–100 ASCII letters, digits, `_ . : -`. No timestamp fallback is invented. Missing routing IDs reject the event before persistence. Names/messages/addresses may be missing or invalid: they are retained as review records. Wrong field types and excessive lengths reject with 422. Unknown extra fields are discarded; keep any additional business context in the documented message or extend the schema intentionally.

Limits: name 200, email 254, phone 40, message 10,000 characters; application request body 32 KiB. Reply permission must be an actual JSON Boolean. Omitted permission means false. Correlation IDs are generated by the service and returned; callers cannot supply log text or correlation IDs.

Response: `lead_id`, `duplicate`, `state` at persistence and `correlation_id`. A duplicate returns the original durable receipt even when a later stage has advanced. A conflicting reused source/event yields application 409; because the n8n HTTP node treats this as a failed execution, its webhook currently returns generic 500. Do not treat that as a new lead: inspect the failure ledger and reuse/correct source identifiers deliberately. A richer webhook error-status mapping is a documented future improvement.

`POST /intake` on the application uses the same intake role and transactional contract. It is available for adapters and fault/recovery testing; normal demonstration submissions enter through n8n.

## Operations API (admin role)

| Method / route | Purpose |
|---|---|
| `GET /api/dashboard` | Aggregate metrics, latest 200 leads, last 50 events/attempts, dead letters |
| `GET /api/leads/{id}` | Original payload, current fields, drafts, timeline, outbox, attempts, contact history |
| `PATCH /api/leads/{id}` | Correct name/email/phone/message/category; increment revision and regenerate eligible draft |
| `POST /api/leads/{id}/decision` | `{ "draft_id": "...", "decision": "approve" }` or reject |
| `POST /api/outbox/{id}/fault` | Set synthetic statuses for subsequent simulator calls |
| `POST /api/outbox/{id}/reconcile` | Resolve a dead-letter only if its simulator receipt exists |
| `POST /api/outbox/{id}/redrive` | `{ "confirm": "retry-approved-draft" }`; new bounded retry budget after explicit inspection |

All admin mutations also require `X-Operator` (1–80 letters, digits, spaces, underscore, dot or hyphen). This is an operator-supplied audit label, not cryptographically verified individual identity. Corrections cannot grant reply permission. Once approved, the enquiry is locked; create a separately reviewed business process for any future amendment/revocation requirements.

For deterministic demonstrations, an approval may additionally include `simulation_faults: [503,200]`, `[429,200]` or `[400]`. This plan commits with the outbox row. Repeating the approval does not replace a prior plan. Supported synthetic statuses: 200, 400, 429, 500, 503. No plan can select a real delivery destination.

## Worker API

`POST /internal/leads/{id}/qualify`, `POST /internal/leads/{id}/draft`, `GET /internal/pending`, `POST /internal/recover`, `POST /internal/outbox/claim`, `POST /internal/deliver` and `POST /internal/orchestration-error` require the worker token. Claim returns `jobs: []` or a job with `outbox_id` and `lease_token`. Deliver consumes that exact job, verifies the approval and lease, and returns the persisted outcome. Never hold claim output indefinitely; default lease is 30 seconds.

## Simulator API

`POST /simulator/send` requires the separate simulator token. The fixed payload is `idempotency_key`, `recipient`, `subject`, `body`. It must exactly match an approved frozen draft associated with that outbox key. Only local SQL receipts are written. Provider URL configuration rejects non-loopback hosts, non-HTTP schemes and any path other than `/simulator/send`. Redirects are not followed.

`GET /health` and static UI assets are public but disclose no lead records. There is no CORS opt-in, public API documentation route or token-in-URL login.
